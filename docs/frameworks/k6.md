# k6

`xk6-edgelens` is a k6 extension that lets you run sustained-load
benchmarks against an EdgeLens device — useful for "does this model
hold 30 fps for 10 minutes" style soak tests that go beyond what a
unit test framework can express.

> **Status:** v0 — see the `xk6-edgelens` README for current status.
> The surface below is the v1 target. Until v1 binaries ship, build
> from source with the snippet below.

## Build

k6 extensions are Go-based and require a custom k6 binary built with
`xk6`:

```bash
go install go.k6.io/xk6/cmd/xk6@latest
xk6 build --with github.com/edgelens-ai/edgelens-sdk/integrations/k6
```

This produces a `./k6` binary in the current directory with the
EdgeLens module compiled in. Drop it in your `$PATH` (or use the
prebuilt binary from
[GitHub Releases](https://github.com/edgelens-ai/edgelens-sdk/releases)
once v1 ships).

## Quickstart

```js
// bench.js
import edgelens from "k6/x/edgelens";
import { check } from "k6";

export const options = {
  scenarios: {
    soak: {
      executor: "constant-vus",
      vus: 1,
      duration: "10m",
    },
  },
  thresholds: {
    inference_fps: ["avg>15"],
    inference_latency_ms: ["p(95)<100"],
  },
};

let session;

// Files must be opened at init scope (a k6 rule); upload them in setup().
const model = open("./models/face.cvimodel", "b");

export function setup() {
  const client = edgelens.connect({ apiKey: __ENV.EDGELENS_API_KEY });
  session = client.createSession({
    deviceType: "recamera-2002",
    os: "stock-os",
  });
  session.waitReady();
  session.device.deploy({ model: { name: "face.cvimodel", data: model } });
  session.device.inference.start();
  return { sessionId: session.id };
}

export default function (data) {
  const stats = edgelens.resume(data.sessionId).device.inference.stats();
  check(stats, {
    "fps holding": (s) => s.fps.avg >= 15,
    "p95 latency": (s) => s.latency_ms.p95 < 100,
  });
}

export function teardown(data) {
  edgelens.resume(data.sessionId).release();
}
```

Run it:

```bash
./k6 run bench.js
```

## Module surface

| Symbol | What |
|---|---|
| `edgelens.connect({apiKey, baseUrl?})` | Creates a client. |
| `client.createSession({deviceType, os, ...})` | Allocates + returns a Session. |
| `edgelens.resume(sessionId)` | Re-attaches to an existing session inside a VU. |
| `session.waitReady({timeout?})` | Block until `status=ready`. |
| `session.device.deploy({model, config?, files?})` | Upload a model, plus optional config and extra files. Each is `{ name, data }`, where `data` comes from `open(path, "b")` at init scope. The upload times out after 10 minutes. |
| `session.device.inference.start()` / `.stop()` | Toggle inference. |
| `session.device.inference.stats()` | Snapshot fps + latency. |
| `session.device.exec(cmd, {timeout?})` | Run a shell command via SSH. |
| `session.release()` | Release the device. |

## Custom metrics

The extension emits two k6 metrics that integrate with thresholds:

- `inference_fps` — frames/sec rollup.
- `inference_latency_ms` — per-frame latency (trend metric, p(95)/p(99) supported).

Wire them into `thresholds` to gate a CI run:

```js
thresholds: {
  inference_fps: ["avg>15"],
  inference_latency_ms: ["p(95)<100", "p(99)<200"],
}
```

k6 exits non-zero when any threshold fails — drop straight into a CI
gate.

## Setup / teardown / VU lifecycle

EdgeLens sessions are expensive (~30 s flash). Allocate in `setup()`,
attach via `edgelens.resume(sessionId)` in each VU, release in
`teardown()`. Do **not** call `createSession` from inside the default
function — every VU iteration would allocate a fresh device.

## Anti-patterns

- One session per VU — see above; allocate in `setup()`, share by id.
- Polling `inference.stats()` from a JavaScript `for` loop — let k6's
  executor manage iteration cadence.
- Threshold expressions referencing fields the extension doesn't emit
  yet (`inference_detection_count` etc., planned for v1.1).
