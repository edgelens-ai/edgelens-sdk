# Pinned dependency set for the `make test` image (Dockerfile.test).
#
# WHY PINNED, and not pyproject.toml's ranges.
#
# Each component's pyproject.toml declares open-ended ranges (httpx>=0.27,
# pydantic>=2.0, pytest>=7.0, mcp[cli]>=1.2,<2, robotframework>=6.0). A test
# image built straight from those resolves to whatever is newest on the build
# day, which makes the suite's result a function of the date rather than of
# the commit. Pinning makes `make test` reproducible: the same commit gives
# the same answer next month. The pyproject.toml files stay the single source
# of truth for WHICH packages the suite needs; this file records WHICH VERSION
# of each, the way a lockfile does.
#
# WHAT PINNING IS NOT FOR.
#
# A version that breaks the suite does NOT belong below. Pin the versions the
# suite passes on; if raising one breaks a test, fix the test rather than the
# pin -- a lockfile that preserves a broken version is a lockfile that stops
# the suite from telling you about the next drift.
#
# Installed with --no-deps and --no-build-isolation (see Dockerfile.test), so
# this list is complete by construction: it is the `pip freeze` of the resolve
# that produced the published image. hatchling is in the list because the
# editable install of each SDK component needs it as a PEP 517 build backend
# at image-build time, and build isolation is off so no network fetch happens
# behind the pin.
#
# REGENERATE deliberately, never casually:
#   1. Build a resolver image that installs the direct dependencies from each
#      component's pyproject.toml with their declared ranges:
#        FROM docker.io/library/python:3.12-slim@<digest>
#        RUN pip install --no-cache-dir hatchling editables \
#              "httpx>=0.27" "pydantic>=2.0" "click>=8.1" \
#              "mcp[cli]>=1.2,<2" "robotframework>=6.0" \
#              "pytest>=7.0" "pytest-httpx>=0.30" "pytest-asyncio>=0.23" \
#          && pip freeze > /pinned.txt
#   2. `podman run --rm resolver:tmp cat /pinned.txt | sort` -- that is this
#      file's body.
#   3. `make -C edgelens-sdk test-rebuild` -- confirm the suite still passes
#      end to end, python and typescript, before committing the new pins.
